# 카페24 배포 가이드 (메디로드 웹사이트)

메디로드 사이트는 **정적 페이지(Next.js 빌드 결과) + PHP API + MariaDB**로 카페24 웹호스팅에서 동작합니다.
Node.js 서버가 필요 없습니다. 아래 순서대로 한 번 설정하면, 이후 수정은 개발 PC에서 `npm run deploy` 한 줄로 배포합니다(11번).

> 카페24 관리 화면의 메뉴 이름과 위치는 화면 개편에 따라 조금씩 다를 수 있습니다. 메뉴를 못 찾으면 "호스팅 관리"에서 검색하세요.

---

## 1. 준비물
| 항목 | 내용 |
| --- | --- |
| 카페24 웹호스팅 | PHP·MariaDB 사용 가능한 상품 (일반형 이상) |
| FTP 접속 정보 | 호스트 `mediroadmap.com`(포트 21), 아이디, 비밀번호. `아이디.cafe24.com`은 FTP 포트가 닫혀 있어 접속되지 않습니다 |
| DB 정보 | DB 이름·아이디(보통 FTP 아이디와 같음), DB 비밀번호 |
| 업로드 파일 | `dist/mediroad-cafe24-YYYYMMDD.zip` (개발 PC에서 `npm run package`로 생성) |
| FTP 프로그램 | FileZilla 등 |

## 2. PHP 버전 설정
1. 카페24 **호스팅 관리 → PHP 버전 설정**으로 들어갑니다.
2. **PHP 8.x**를 선택합니다. 권장은 8.1 이상이고, 최소 7.4 이상이어야 합니다.
3. 필요한 확장은 **PDO MySQL, GD, mbstring, fileinfo**입니다. 카페24 기본 구성에 포함되어 있습니다.
   - 사진 업로드가 "GD 확장이 없어" 오류를 내면 카페24 고객센터에 문의하세요.

## 3. DB 준비
1. **호스팅 관리 → DB 관리**에서 DB가 생성되어 있는지 확인합니다. 웹호스팅은 가입할 때 DB가 1개 만들어집니다.
2. DB 비밀번호를 모르면 같은 화면에서 재설정합니다.
3. DB 문자셋은 **utf8mb4**를 권장합니다. 설치 스크립트가 테이블마다 utf8mb4를 지정하므로 따로 바꾸지 않아도 됩니다.
4. 기록해 둘 값:
   - 호스트: `localhost` (카페24 웹호스팅 기본값)
   - DB 이름, DB 아이디, DB 비밀번호

## 4. 파일 업로드 (최초 배포)
1. 개발 PC에서 zip을 만듭니다.
   ```bash
   npm run package        # next build → dist/cafe24/ → dist/mediroad-cafe24-YYYYMMDD.zip
   ```
2. zip을 풀면 아래 구조가 나옵니다. **이 안의 내용 전체**를 FTP **접속하면 처음 보이는 폴더(사이트 루트)**에 올립니다. 이 호스팅은 `/www/` 폴더가 따로 없고, 첫 폴더가 곧 웹 루트입니다.
   - `.htaccess`처럼 점으로 시작하는 숨김 파일도 반드시 함께 올려야 합니다. FileZilla는 "서버 → 숨김 파일 표시 강제"를 켜세요.
   ```
   (FTP 루트)/
   ├─ .htaccess          ← 페이지 라우팅·보안 규칙 (필수)
   ├─ router.php         ← 로그인·매물 메뉴 노출 확인 후 페이지 서빙
   ├─ index.html, about/, analysis/, support/, location/, admin/, _next/, images/ …
   ├─ api/               ← JSON API
   ├─ app/               ← PHP 공용 코드·설정 (웹 접근 차단)
   │   ├─ config.sample.php
   │   └─ storage/       ← 로그·세션 (쓰기 권한 필요)
   ├─ uploads/           ← 매물 사진 (쓰기 권한 필요, PHP 실행 차단)
   └─ install/           ← 최초 1회 설치
   ```
3. 폴더 권한: `app/storage/`와 `uploads/`는 **웹서버가 쓸 수 있어야** 합니다.
   - 카페24는 보통 기본값(755)으로 동작합니다.
   - 사진 업로드나 로그인이 실패하면 FTP 프로그램에서 두 폴더 권한을 `755`로 확인하고, 그래도 안 되면 `707`로 바꿔 보세요.

## 5. 설정 파일 만들기 (config.php)
1. `app/config.sample.php`를 **같은 폴더에 `config.php`라는 이름으로 복사**합니다.
2. `config.php`를 열어 값을 **직접** 입력합니다. `getenv(...) ?:` 부분은 지우고 따옴표 안에 값만 남깁니다.
   ```php
   return array(
       'db' => array(
           'host' => 'localhost',
           'port' => '3306',
           'name' => 'DB이름',
           'user' => 'DB아이디',
           'pass' => 'DB비밀번호',
       ),
       'site_url' => 'https://www.mediroadmap.com',   // 끝에 / 없이
       'mail_mode' => 'mail',
       'mail_from' => 'no-reply@mediroadmap.com',
       'mail_from_name' => '메디로드',
       'notify_email' => '',                           // 새 상담 문의 알림 받을 주소 (비우면 알림 없음)
   );
   ```
3. `config.php`는 **zip에 들어 있지 않습니다.** 이후 업데이트 배포 때 덮어써지지 않으니 서버에만 보관하세요.

## 6. 설치 실행 (/install)
1. 브라우저에서 `https://도메인/install/`로 접속합니다.
2. **관리자 이메일·이름·비밀번호**(8자 이상)를 입력합니다.
   - 화면 확인용 예시 매물이 필요하면 "예시 매물 넣기"를 체크합니다.
3. "설치하기"를 누르면 아래 작업이 진행됩니다.
   - 테이블 생성
   - 관리자 계정 생성
   - 기본 설정("매물 정보" 메뉴 노출 = 켬)
   - 예시 매물 추가 (체크한 경우)
4. 설치가 끝나면 `install/.lock`이 생기고 설치 화면이 **잠깁니다.** 관리자 계정이 있어도 잠깁니다.
   - **보안을 위해 FTP에서 `install/` 폴더를 삭제**하세요.
5. 오류가 나면:
   - "설정 파일이 없습니다": `app/config.php` 이름·위치를 확인합니다.
   - "DB에 연결하지 못했습니다": config.php의 DB 값을 확인합니다.

## 7. 관리자 로그인과 오픈 전 점검
1. `https://도메인/login/`에서 관리자 계정으로 로그인한 뒤 `https://도메인/admin/`으로 들어갑니다.
2. 확인할 것:
   - [ ] **매물 관리**: 예시 매물을 넣었다면 오픈 전에 **"예시 매물 전체 삭제"** 버튼으로 지웁니다.
   - [ ] **매물 등록**: 사진 업로드 → 저장 → 회원 화면(`/location/`)에 보이는지 확인합니다.
   - [ ] **거래완료 처리**: 계약이 끝난 매물은 통보받은 날부터 3일 안에 "거래완료" 또는 "비노출"로 바꿉니다. 회원 화면에서 즉시 사라집니다.
   - [ ] **상담 문의**: `/contact/`에서 테스트 문의를 넣고 관리자 목록에 뜨는지 확인한 뒤 삭제하거나 "완료" 처리합니다.
   - [ ] **설정**: "매물 정보" 메뉴 노출을 끄면 헤더·홈의 매물 링크가 사라지고, `/location/` 주소로 들어오면 홈으로 이동합니다(관리자는 계속 볼 수 있음).
3. 일반 회원 가입 확인: 로그아웃한 뒤 `/signup/`에서 가입 → `/location/` 접근을 확인합니다.
4. 첫 관리자 외에 관리자를 더 두려면, 가입한 계정을 DB 관리(phpMyAdmin)에서 `users.role`을 `admin`으로 바꿉니다.

## 8. 도메인·SSL(https)
1. **도메인 연결**: 카페24 호스팅 관리의 "도메인 연결"에서 `mediroadmap.com`, `www.mediroadmap.com`을 연결합니다.
   - 도메인을 다른 곳에서 샀다면 그쪽 DNS에 카페24가 안내하는 네임서버 또는 A 레코드를 입력합니다.
2. **SSL 인증서**: 카페24의 SSL 인증서(무료 또는 유료)를 신청·설치합니다.
3. **대표 주소 통일(적용 완료, 2026-10-15)**: `.htaccess`가 `http://`·www 없는 주소를 모두 `https://www.mediroadmap.com`으로 301 이동시킵니다. 검색엔진 중복 페이지를 막는 설정이니 지우지 마세요.
   - 도메인이 바뀌면 `server/.htaccess`의 `mediroadmap.com` 두 곳과 `content/site.config.json`의 `siteUrl`을 함께 바꿉니다.
   - 인증서 갱신 경로(`/.well-known/`)는 이동 대상에서 빠져 있습니다.
4. `config.php`의 `site_url`이 실제 주소(https, www 포함 여부)와 같은지 확인합니다. 비밀번호 재설정 메일 링크에 쓰입니다.
5. 로그인 쿠키는 https 접속이면 자동으로 Secure로 설정됩니다.

## 9. 메일 발송 확인
- 비밀번호 재설정 메일과 새 문의 알림 메일은 PHP `mail()`로 보냅니다(카페24 웹호스팅 지원).
- 확인 방법: `/forgot-password/`에서 가입한 이메일을 입력한 뒤 메일함과 스팸함을 확인합니다.
- 메일이 스팸으로 가거나 오지 않으면:
  - `mail_from` 주소를 사이트 도메인 주소로 맞춥니다. 예: `no-reply@mediroadmap.com`
  - 도메인 DNS에 SPF 레코드를 추가합니다. 카페24 메일 발송 서버를 허용하는 값이며, 카페24 안내를 따르세요.
  - 하루 발송량 제한이 있을 수 있으니, 대량 발송이 필요하면 외부 메일 서비스를 검토합니다.
- 새 문의 알림은 `notify_email`을 입력해야 발송됩니다. 받는 방식(메일·문자 등)은 클라이언트 확인 후 확정합니다.

## 10. 백업
| 대상 | 방법 | 주기 |
| --- | --- | --- |
| DB (회원·매물·문의·설정) | 카페24 DB 관리(phpMyAdmin) → 내보내기(SQL), 또는 카페24 자동 백업 서비스 | 매주 + 대규모 수정 전 |
| 매물 사진 `uploads/` | FTP로 폴더 전체 다운로드 | 매주 |
| 설정 `app/config.php` | FTP로 다운로드해 안전한 곳에 보관 (비밀번호 포함, 공유 금지) | 변경 시 |

- 로그 `app/storage/php-error.log`와 `mail.log`는 필요할 때만 FTP로 확인하고, 커지면 삭제해도 됩니다.

## 11. 업데이트 배포 (사이트 수정 후 다시 올릴 때)

### 방법 A — `npm run deploy` (권장, 개발 PC)
바뀐 파일만 골라 FTP로 올리고, 운영 사이트를 바로 점검합니다. 보통 10~30초 걸립니다.
```bash
npm run deploy                    # 빌드(npm run package) → 바뀐 파일만 업로드 → 운영 사이트 점검
npm run deploy -- --dry-run       # 올릴 파일 목록만 확인
npm run deploy -- --no-build      # 이미 만든 dist/cafe24 를 그대로 올림
```
- **필요한 것**: 저장소 루트의 `Ftp.md`에 `ftp : FTP비밀번호` 줄. 이 파일은 `.gitignore` 대상이라 커밋되지 않습니다. 환경변수 `FTP_PASSWORD`가 있으면 그 값을 씁니다.
- **어떻게 고르나**: 마지막 배포 때 올린 파일의 해시를 `.deploy-manifest.json`(커밋 안 됨)에 남기고, 달라진 파일만 올립니다. 이 파일이 없으면 전체를 올립니다.
  - 다른 PC에서 배포했거나 FileZilla로 직접 올려 기록이 맞지 않으면, 한 번 전체를 올리거나(`.deploy-manifest.json` 삭제 후 `npm run deploy`) 서버와 같다고 확신할 때만 `npm run deploy -- --mark-deployed`로 기록을 맞춥니다.
- **올리는 순서**: JS·CSS → 이미지 등 → 페이지(html·txt) → `.htaccess`. 새 페이지가 아직 안 올라간 JS를 가리키는 순간이 생기지 않게 합니다.
- **올리지 않는 것**: `app/config.php`, `app/storage/`(로그·세션), `uploads/`(매물 사진), `install/`(보안).
- **점검**: 주요 페이지 8개의 응답 코드와 홈이 쓰는 JS·CSS가 서버에 모두 있는지 확인합니다. `✓ 운영 사이트 점검 통과`가 나오면 끝입니다.
- 업로드가 중간에 실패하면 기록을 갱신하지 않으므로, 원인을 고친 뒤 다시 실행하면 됩니다.

### 방법 B — FileZilla로 직접 올리기
1. 개발 PC에서 `npm run package`로 새 zip을 만듭니다.
2. zip을 풀어 FTP 루트에 **덮어쓰기** 업로드합니다. 아래 파일·폴더는 zip에 없거나 비어 있어 **서버 데이터가 유지**됩니다.
   - `app/config.php`: zip에 포함되지 않음
   - `uploads/listings/`: 매물 사진. zip에 포함되지 않음
   - `app/storage/`: 로그·세션. zip에는 차단용 `.htaccess`만 있음
3. 방법 B로 올린 뒤 방법 A를 쓰면 `.deploy-manifest.json` 기록이 서버와 다를 수 있습니다. 위 "다른 PC에서 배포했거나…" 항목대로 맞춥니다.

### 공통 주의
- **절대 하지 말 것:** FTP 루트 전체를 지우고 새로 올리기. config.php와 매물 사진이 사라집니다.
- 페이지가 사라지거나 이름이 바뀐 경우, 남아 있는 옛 HTML 폴더는 FTP에서 지워도 됩니다. 두 방법 모두 서버 파일을 지우지는 않습니다.
  - `_next/` 폴더는 빌드마다 파일명이 달라져 쌓입니다. 정리하려면 통째로 지운 뒤 `.deploy-manifest.json`을 삭제하고 `npm run deploy`로 전체를 다시 올립니다. `_next/`에는 서버 데이터가 없습니다.
- DB 구조가 바뀐 업데이트라면 개발자가 안내하는 SQL을 phpMyAdmin에서 실행합니다. `install/`은 다시 올리지 않습니다.
- 배포 후 검색엔진에 빨리 알리려면: 구글 서치콘솔 **URL 검사 → 색인 생성 요청**, 네이버 서치어드바이저 **요청 → 웹 페이지 수집**에 바뀐 페이지 주소를 넣습니다.

## 12. 문제 해결
| 증상 | 확인할 것 |
| --- | --- |
| 모든 페이지가 500 오류 | `.htaccess` 업로드 여부, PHP 버전 7.4 이상인지. 호스팅이 `.htaccess`의 `Header` 지시어를 막는 경우 `<IfModule mod_headers.c>` 블록을 지워 봅니다 |
| 홈은 되는데 하위 페이지가 404 | `.htaccess`가 없거나 mod_rewrite가 꺼져 있음 → `.htaccess` 재업로드 |
| 로그인이 계속 풀림 | `app/storage/`에 쓰기 권한이 없음 (세션 저장 폴더 `app/storage/sessions`) |
| FTP 접속 시간 초과 | 호스트를 `mediroadmap.com`으로 썼는지(`아이디.cafe24.com`은 FTP 포트가 닫혀 있음) |
| FTP 로그인 거부(530) | FTP 비밀번호는 카페24 로그인 비밀번호와 다를 수 있음 → 호스팅 관리 → FTP 비밀번호 변경에서 확인 |
| 사진 업로드 실패 | `uploads/` 쓰기 권한, 사진 15MB 이하·JPG/PNG/WEBP 여부, 카페24 PHP 업로드 한도(`upload_max_filesize`) |
| "설정 파일 없음" | `app/config.php` 파일 이름·위치 |
| 비밀번호 재설정 메일 안 옴 | 스팸함, `mail_from`, SPF, `site_url` |
| 매물 메뉴가 안 보임 | 관리자 → 설정에서 "매물 정보 메뉴 노출"이 켜져 있는지 |

## 부록: 개발 PC에서 카페24 환경 흉내 내기 (Docker)
