# 메디로드 개편 사양 (2026-09-15)

전달사항 문서 + 추가 요청(카페24 PHP 배포, 입지 분석 중심 개편)을 한 곳에 고정한 개발 기준 문서입니다.
작업자(문구 · PHP · 프론트)는 이 문서의 주소·필드·API 규약을 그대로 따릅니다.

## 0. 추가 요청 요약
1. "약국 개설" → "약국 개국" 전면 교체 (법령상 절차명이 꼭 필요한 곳만 "약국개설등록(약사법)" 괄호 병기)
2. 메인 키워드 "컨설팅" → "입지 분석"
3. 문구 재작성: 컨설팅 비중 축소, 입지 분석 중심
4. 서브 페이지 추가: 전문 행정사와 함께하는 인증·개설·허가 절차 지원 (인증, 개설, 허가, 외국인환자 유치, 서류 절차)
5. 경영마케팅 페이지: "경영마케팅 전문기업 플라노바와 함께합니다" 추가
6. 각 페이지 메인 비주얼: 입지 분석 자료(지도·반경·인구·유동인구·경쟁 분포·차트)를 다양하게 활용
- 법인 표기 "메디로드 개원 컨설팅"은 사업자등록증 상호이므로 푸터·약관·개인정보처리방침의 **상호 표기만** 유지

## 1. 배포 구조 (카페24 웹호스팅)
- 카페24 웹호스팅은 Node.js가 없으므로 **Next.js 정적 내보내기(`output: "export"`, `trailingSlash: true`) + PHP API + MySQL(MariaDB)**.
- Supabase는 쓰지 않음.
- 업로드 패키지(`dist/cafe24/` → zip) 구조 (웹 루트 `www/` 기준):
```
.htaccess            # 페이지 요청 → router.php, 보안 규칙
router.php           # 정적 HTML 서빙 + 접근 제어 + <html> 속성 주입 + 옛 주소 301
index.html, about/…, _next/…, images/…   # next build 결과(out/)
api/…                # JSON API (PHP)
app/                 # PHP 공용 코드·설정 (웹 접근 차단)
  config.sample.php  # → config.php 로 복사해 DB 정보 입력 (패키지에 config.php 는 넣지 않음)
uploads/             # 매물 사진 (PHP 실행 차단)
install/             # 최초 1회 설치 (테이블 생성·관리자 계정·예시 매물), 설치 후 잠김
```
- 대상 PHP 7.4 이상 호환 코드 (match, nullsafe, str_contains, named args, union type 사용 금지). PDO MySQL, GD, mbstring.
- 로컬 테스트: `docker compose` (php:8.2-apache + mariadb:10.6), `http://localhost:8080`.

### router.php 규칙
- 요청 경로 정규화: 확장자 없는 경로에 `/`가 없으면 301로 `/` 붙이기. `/x/y/` → `x/y/index.html`, 없으면 `404.html`(404 상태).
- **옛 주소 301**: `/consulting` → `/analysis/`, `/consulting/opening` → `/analysis/clinic/`, `/consulting/pharmacy` → `/analysis/pharmacy/`, `/consulting/transfer` → `/analysis/transfer/`, `/consulting/marketing` → `/support/marketing/`, `/consulting/closure` → `/support/closure/`, `/consulting/roadmap` → `/analysis/clinic/`.
- **접근 제어**
  - `/location/…`: 로그인 안 했으면 302 `/login/?next=<원래 경로+쿼리>`. 입지 메뉴 미노출이면 관리자 외에는 302 `/`.
  - `/admin/…`: 로그인 안 했으면 302 `/login/?next=…`, 관리자가 아니면 302 `/`.
  - `/login/`, `/signup/`: 이미 로그인했으면 `next` 또는 `/`로 302.
- **HTML 속성 주입**: `<html lang="ko"` → `<html lang="ko" data-auth="guest|member|admin" data-loc="on|off"`. 모든 HTML 응답 `Cache-Control: no-cache`.
- `next` 파라미터는 `/`로 시작하고 `//`로 시작하지 않을 때만 허용.

## 3. 콘텐츠 JSON 필드 (문구 담당이 채우고, 프론트가 읽음)

### content/site.config.json
- `brand.title` 유지, `brand.description` = 입지 분석 중심 한 줄.
- `brand.keywords`는 삭제하고 `content/seo.json`으로 이동.
- `menu.items`: 위 표의 5개 메뉴 (children 포함). 매물 정보 항목과 그 children 에는 `"locOnly": true`.
- `pages`: 서브 비주얼 문구. 키는 경로(`/about`, `/analysis`, `/support`, `/contact`, `/location`, `/login`, `/signup`, `/forgot-password`, `/reset-password`, `/terms`, `/privacy`, `/admin`), 값 `{ en, title, desc, visual }`.
  - `visual`은 아래 비주얼 종류 중 하나 또는 `""`.
- `home.services`: 홈 분야 목록 6개(입지 분석 3 + 개원 지원 3). 각 `{ en, title, desc: string[], href, img, group }`.
- `home.location`: 홈 매물 섹션 문구 `{ en, title, desc, more, lockedTitle, lockedDesc }`. lockedTitle·lockedDesc는 비회원에게 보이는 문구.
- `home.contact`: CTA 문구 `{ title, en, headline, desc, image }`.
- `seo.verification`: `{ google: "", naver: "" }`.

## 5. DB 스키마 (MariaDB 10.x, utf8mb4)
- `users`: id, email(UNIQUE), password_hash, name, phone, role ENUM('member','admin'), created_at, last_login_at
- `password_resets`: id, user_id, token_hash CHAR(64), expires_at, used_at, created_at
- `login_attempts`: id, ip, email, attempted_at. 10분 내 10회 실패 시 잠시 차단
- `listings`
  - 기본: id, code(UNIQUE, `L-YYYY-NNN` 임대·분양 / `S-YYYY-NNN` 매매 자동 생성), deal_type ENUM('임대','분양','매매'), category, title, region, address
  - 가격: deposit_manwon INT NULL, rent_manwon INT NULL, sale_price_manwon INT NULL, price_note VARCHAR
  - 면적·층: area_m2 DECIMAL(8,2), floor_current VARCHAR(10), floor_total INT
  - 건물 정보: use_type VARCHAR, approval_date DATE, direction VARCHAR, parking INT, maintenance_manwon INT, move_in VARCHAR, violation TINYINT
  - 내용: features TEXT(JSON 배열), description TEXT, images TEXT(JSON 배열), lat, lng
  - 상태: status ENUM('open','closed','hidden'), closed_at, is_sample TINYINT, sort_order INT, created_at, updated_at
- `inquiries`
  - 신청 정보: id, name, phone, email, department, region, open_timing, budget, deposit, rent, facility_cost, area, facility, consult_type, message
  - 처리: status ENUM('new','in_progress','done'), memo TEXT, ip, created_at, updated_at
- `settings`: skey PK, svalue TEXT (`location_menu_visible` = '1')

### 매물 필수값 (서버 검증, 422 + errors{필드: 메시지})
- **공통 필수:** 소재지(address), 면적(area_m2>0), 용도(use_type), 거래형태(deal_type), 층수(floor_current·floor_total), 사용승인일(approval_date), 방향(direction), 주차대수(parking≥0), 관리비(maintenance_manwon≥0), 입주가능일(move_in), category, title, region
- **가격 (거래형태별):**
  - 임대: deposit_manwon·rent_manwon 필수
  - 분양: sale_price_manwon 필수
  - 매매: sale_price_manwon 필수 (보증금·월세는 선택)
- 가격은 정수(만원)만 저장한다. 그래서 "협의"만 적는 것은 구조적으로 불가능하고, price_note는 보조 문구다.
- 거래완료(closed)·비노출(hidden)은 회원 화면에서 즉시 제외한다. closed로 바꾸면 closed_at을 기록한다.
- 목록 탭: `lease` = 임대+분양, `sale` = 매매

## 6. JSON API 규약 (`/api/…`)
- **응답:** 성공 `{ "ok": true, … }`, 실패 `{ "ok": false, "error": "메시지", "errors"?: {필드: 메시지} }` + HTTP 상태(400/401/403/404/405/422/429/500)
- **요청:** 상태를 바꾸는 요청은 POST + `Content-Type: application/json` + 헤더 `X-Requested-With: mediroad` (없으면 403, CSRF 방지). 업로드만 multipart.
- **세션:** PHP 세션 쿠키 `MRSESSID` (HttpOnly, SameSite=Lax, HTTPS면 Secure). 로그인 시 `session_regenerate_id`.

## 7. 알림·메일
- 비밀번호 재설정 메일: PHP `mail()` (카페24 지원).
  - 제목은 UTF-8 base64 인코딩, 발신 주소는 `config.php`의 `mail_from`.
  - `mail_mode = 'log'`이면 `app/storage/mail.log`에 기록한다(로컬 테스트용).
- 새 상담 문의 알림: `config.php`의 `notify_email`이 비어 있지 않으면 같은 방식으로 메일을 보낸다. 방식은 클라이언트 확인 후 확정한다.
